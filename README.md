# Engineering Change Process: Before and After

**Live:** https://woyakn77-create.github.io/engineering-change-process/ · [Back to portfolio](https://woyakn77-create.github.io/portfolio/)

When a product's design changes, the change has to pass through engineering, purchasing, manufacturing and quality before the new version can be built. This page maps that process at two manufacturing sites, measures where the time goes, and proposes a faster future state.

## What it shows
- **Two examples:** Site A, a design change to an in-house bracket. Site B, a component switch to a new supplier.
- **Process flow** for the current and future state, color-coded by team, with decision loops for alignment and test results.
- **Value stream map** with hands-on time, waiting time, lead time and % value-added.
- **Ten improvements (kaizen)**, each tied to the waste it removes: standard request form, weekly change board, async alignment in a shared document, time-limited digital approvals, parallel processing, AI-drafted work instructions, validation planned at approval, a results template, a release checklist and single data entry.

## Result (illustrative estimates)
| | Current | Future |
|---|---|---|
| Site A lead time | 47.6 working days | 16.7 (-65%) |
| Site B lead time | 57.3 working days | 18.5 (-68%) |

## Methods
Process mapping · value stream mapping · lean waste identification · kaizen · standard work · parallel processing · AI assistance
